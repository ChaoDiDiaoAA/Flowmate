# 综合票据核验参考（明确制作的评测用合编）

以下16个章节原文复用仓库各Skill参考文件；章节标题仅用于导航。当前日期任务只需日期章节，其他内容不扩大权限或业务范围。


## 章节：invoice

# 发票字段与缺失表达

头字段包含 invoiceNumber、issueDate、sellerName、buyerName、currency、totalAmount，以及 netAmount、taxAmount；具体结构和其他字段遵循当前候选工具契约。

- 模型候选中的 present 需要非空 raw 和可核验 sources。来源引用完整保留工具返回的 documentId、version、artifactId、page、blockId、quote；不猜测或拼造引用。
- normalized 尚未解决时可以保持 null，并解释真实规范化诊断。非 present 的 normalized 必须为 null。
- ambiguous 表示至少两个有证据依据的替代值；alternatives 不是来源对象，不足两个依据时使用 missing 或 unreadable 说明情况。
- missing 表示没有取得字段；unreadable 表示已有资料无法辨认。两者都不能替换成零、空字符串或推测值。
- missing 和 not_applicable 不得附 alternatives。not_applicable 需要在 notes 中写出包含对应字段名称的具体原因。
- 金额和日期使用当前 normalize_invoice_values 处理，sources 通过 check_invoice_sources 核验，候选通过 validate_invoice_candidate 检查。saveable=true 只表示验证结果；保存、接受和表单应用遵循各自真实工具回执。

这些规则用于指导读取和表达。实际结构、来源及数值检查由现有业务代码执行，资源内容不增加工具权限或业务执行资格。


## 章节：invoice-amount-reconciliation

# 核算边界

- 金额由精确十进制字符串交给工具；计算过程不使用 JavaScript 浮点或口算结果作为权威值。
- scale 依据材料币种与当前工具规则确定，未明精度时区分精确结果和未确定的舍入结果。
- 当前 calculate_invoice_amounts 的舍入事实由返回的 rounding 指定；结果展示保留 exact 与 rounded 的差别。
- 不同币种分别核算，不在没有汇率依据时相加。负数、折扣和冲销按材料真实符号保留。
- 含税与未税单价、百分比与小数税率根据材料及工具 schema 确认；含义不清时报告未确认。
- 差异与容差由当前校验工具规则决定；本 Skill 不自行宣告某个差额允许忽略。
- missing/unreadable 金额不可作为零输入。计算失败或缺输入的项目保持未核算。


## 章节：invoice-candidate-comparison

# 候选比较范围

- ID 与 sequence 使用工具返回值。显示顺序不能代替版本身份；只比较当前任务允许访问的候选。
- 字段值、状态、来源、检查及问题分别报告；normalized 相同不代表原始证据和状态完全相同。
- 行变化使用工具返回的路径/身份，不能仅凭列表下标推定同一业务行。
- 数量或金额差异直接引用工具结果；此 Skill 的工具范围不包含金额重新计算，需要时说明后续核算。
- 人工编辑、模型候选、已保存或已接受是不同事实，按真实候选状态解释。
- 比较结果不是“最佳候选”的自动决定。缺少任务偏好或证据时列出选择所需条件。
- 比较结束不调用写入或表单工具。


## 章节：invoice-candidate-issue-triage

# 问题分级与解释

- severity、origin、code、rule 与 fieldPaths 使用实际结果。保存结果中的 checks/issues 是当时记录，不能宣称已针对当前新材料重跑验证。
- failed 表示相应规则未通过；not_evaluable 表示缺少判断条件；not_applicable 表示规则不适用。它们不能合并显示为 passed。
- error 优先呈现，warning 单独保留；严重程度相同且无额外任务要求时保留原次序，不假造评分、监管风险级别或金额损失。
- 同一问题涉及多个字段可以合并叙述，但保留原 code、字段路径和引用；合并条数与原 issues 数量分开说明。
- valueOrigin=user-provided 的人工值不能伪造来源。它与模型从材料提取的字段分别说明，不把人工值转换为已证实的原票面事实。
- 已保存说明存在保存记录，不等于已接受、表单已应用、业务已完成或税务合规。
- 建议下一步限定为能补充证据、澄清歧义或由用户执行的现有操作。不得自动修复、调用保存/Fill 或把建议写成已执行。


## 章节：invoice-candidate-save

# 保存闭环

- 本 Skill 仅允许用户显式调用；资源启用不扩大 effect 或 scope，工具不可用时说明任务不具备保存资格。
- 草稿字段的 raw/state/normalized/sources 与当前 schema 一致。缺失或无法辨认的值保留状态，不补造号码、主体、金额或引用。
- 校验中的 saveable 与保存成功是不同事实；来源/数值/结构检查由当前业务工具执行。
- 保存工具仍执行自己的合法性检查，不能把前次校验结果当作绕过它的许可证。
- 同一原工具调用的回执和ID为权威依据。异常、断线或停止之后，向用户说明未知状态，并沿原查询核事实；此 Skill 不提供任意重试或新身份重放。
- 工具返回失败时保留待修正稿和真实错误；报告成功必须包含真实候选引用。
- 接受、人工修改、Fill和导出沿独立产品流程；本次授权止于保存候选。


## 章节：invoice-conflict-review

# 冲突规则

- ambiguous 的 alternatives 至少两个有依据的值；来源完整性和替代值支持关系分别报告。
- 格式不同不必然是内容冲突。此 Skill 不具备规范化工具时保留原文差异并请求进一步核验。
- 相同金额的净额/税额/总额标签不同、相同名称的买卖方关系不同，先核语义归属再比较值。
- 新旧版本材料的差异不自动替换当前 Run 的冻结版本；明确说明版本与范围。
- 不用票面常见规律、常见号码或当前时间选择某个替代值。
- 若仅有一个来源且字符无法辨认，应报告 unreadable；没有可靠来源则报告 missing。
- 复核结论不自动保存或接受候选，下一步使用当前任务允许的真实工具。


## 章节：invoice-date-currency-review

# 日期与币种判断规则

- issueDate 只对应明确的开票日期。付款、到期、打印、配送日期不自动替代；日期之间相等也不能证明标签相同。
- normalize_invoice_values 返回 ambiguous 时保留真实 alternatives，normalized 为 null；不能根据操作系统语言、当前日期或常见格式排除其中一个。
- 工具的 currency 规范化只接受其已支持的三字母代码。单独的 $、¥ 等符号不证明某个特定币种；需材料中的明确代码或文字说明。
- 小写代码可以按工具真实结果规范化为大写；地区惯例或模型知识不能代替材料证据。
- 多币种同时出现时，分别列出金额对应的标签及来源。无明确对应时保持 ambiguous，不把其中一种币种应用到全部金额。
- 不声明税务适用日期、付款合法性、汇率或汇兑金额。材料不足时请求显示完整日期/币种栏位的来源。
- 输出示例列：字段/标签 | raw | status | value/alternatives | reason | 来源 | 待确认条件。


## 章节：invoice-evidence-discovery

# 定位规则

- 实际页号来自工具返回值。页号不连续时逐项使用返回的页号；列表下标不是页号。
- 搜索结果是线索。用于字段结论的文本从 read_invoice_evidence 取得完整引用；搜索命中数不能代表资料完整。
- 相同原文出现在不同页或块时分别保留来源，说明是重复、补充还是冲突；仅凭文字相同不合并出处。
- 表格跨页时先保留页/表/行位置，再判断列标题是否延续。无法建立连续关系时分别报告片段。
- 当前工具只返回解析文本和来源时，无法辨认的图像内容保持未确认；需要人工查看的材料明确列出。
- 输出只列与本任务有关的证据和缺口。路径、日志或 Skill 文件本身不能作为发票字段的业务来源。


## 章节：invoice-form-readiness-review

# 填入前核对

- 当前候选引用、实际表单状态和适用修订号是不同身份；只报告已取得的事实。
- 头字段和明细的原值、规范化值、来源、未知项分别列出，避免把缺失转换成空字符串或零。
- 明细来源按真实行身份映射，不能把显示下标当永久行引用。
- validate_invoice_candidate 的 saveable 仅描述候选检查，不能据此宣告表单已准备好或已应用。
- 尚未读取的目标表单条件、人工改动冲突和映射缺口分别标注；当前工具范围不支持查询的内容由用户在真实表单流程复核。
- 本 Skill 的完成物为复核报告。Fill Run 保持唯一 fill_invoice_form 工具，其应用/停止/保存回执沿原产品契约。
- 就绪报告不自动发送聊天、保存候选、接受候选或导出文件。


## 章节：invoice-header-extraction

# 头字段判定

常见头字段为 invoiceNumber、issueDate、sellerName、sellerTaxId、buyerName、buyerTaxId、currency、netAmount、taxAmount、totalAmount，具体以当前工具 schema 为准。

- present 保留非空 raw 和真实来源；normalized 可以在规范化尚未解决时为 null。
- 号码、税号等身份字段保留前导零及标点。标签关系和证据决定归属，不能从常见格式推定某个主体。
- 日期存在多种解释时保留原文并标明歧义；不能用当前日期补全。
- 币种以材料明示或工具核验结果为准；货币符号有多种含义时保持待确认。
- 未取得字段用 missing，已有区域无法辨认用 unreadable；不适用须说明对应字段的具体依据。
- ambiguous 至少需要两个有证据的替代值；保留替代值和出处，无法建立两个依据时保持缺失或无法辨认。
- 非 present 的 normalized 为 null；missing/not_applicable 的 alternatives 为空。


## 章节：invoice-line-calculation-review

# 逐行计算规则

- 用当前行的表头、单位与来源确定 quantity、unitPrice、netAmount、taxRate、taxAmount、totalAmount；续行归属不明确时先报告缺口。
- quantity×unitPrice 只与含义一致的行金额比较。若单价含税、存在折扣/附加费用或价格单位不同，不擅自用该乘积证明净额。
- calculate_invoice_amounts 的 taxRate 是十进制比例；票面明确 13% 时比例为 0.13，记录该单位转换及原文。只有裸数字 13 且单位未知时不能选 0.13 或 13。
- normalize_invoice_values 不解析百分号或千位分隔格式。不支持的 raw 不冒称已规范化；必要的明确单位转换注明依据，不能用猜测填补格式歧义。
- decimal 输入服从真实工具 schema，包括精度及字符限制；超限时说明不能计算，不截断数值后继续。
- 只在材料或任务明确给出 scale 时采用该精度；否则使用 exact 和 scale=null。工具 rounding 为 half_away_from_zero，不能宣称其他舍入方式也已检验。
- 明细金额不同币种、含税/未税口径不明或缺输入时标记不能计算。净额加税额只在币种和口径相同且未存在其他费用时核对总额。
- 输出：行来源 | 算式与输入 | exact/rounded | 票面值 | 比较结论 | 舍入/缺口。差异不自动触发更正、保存或 Fill。


## 章节：invoice-line-item-extraction

# 列与行的映射

- 行身份由当前工具/候选返回的位置或标识确定；表格显示下标不能替代源行引用。
- 数量、单价、税率、净额、税额、总额分别映射。一个金额只有明确标签或列关系时才归入某字段。
- 合计、折扣、运费与商品行按材料呈现分别保留；无法判断是否属于行金额时说明缺口。
- 跨页表头重复与同一行续接是两种事实，分别核对页、表、列关系；没有证据时保留独立片段。
- 所有数值保留 raw，规范化使用精确十进制字符串；空白金额和未识别值不转换为零。
- 一个块覆盖多个行时引用真实块及支持该行的 quote；来源对象完整保留，不编造不存在的子 blockId。
- 明细整理结束只说明材料和字段状态，金额核算交给当前金额工具或对应核算 Skill。


## 章节：invoice-missing-info-review

# 缺口判定与补充要求

- missing：当前可读范围中没有取得对应字段；同时说明检视范围，不能声称已穷尽未提供的材料。
- unreadable：材料中有对应区域或证据但无法取得可辨认值；列出需要更清晰资料或人工确认的位置。
- not_applicable：任务或材料有具体依据证明字段不适用；notes 写出对应字段名及原因。
- 只找到一个不确定片段时保留未知，不构造无依据的第二个替代值。
- 空白、缺失、未确定币种及金额均保留状态；normalized 为 null，不转换成零或推测值。
- 补充问题包含对象和判断目标，如需要哪个页/区域、哪个主体或哪项金额的说明；不索取与任务无关的信息。
- 区分阻断当前处理的缺口和仅影响补充分析的缺口，按真实任务所需排列。


## 章节：invoice-party-role-review

# 买卖方判断规则

- buyer/seller 以材料中的购买方/销售方或等价明确标签为依据。收款方、收货方、银行、经办人及签章名称不自动等于买卖方。
- 同一块包含多个名称时，区分列、标签及相邻关系；仅在对应关系明确时归属。文本顺序不能单独证明角色。
- 税号按原文保留字符与前导零，不凭号码形状、字符长度或国家常见规则更正。税号本身也不能证明角色。
- 名称与税号分别核验；找到名称不意味着已找到其税号。局部可辨时保留 raw，无法可靠辨认的值为 unreadable。
- 同一个主体同时出现在多种角色时，分别列出材料支持的角色；有多个有依据的解释时保持 ambiguous，并列出各来源。
- check_invoice_sources 只验证当前文档的引用身份及原文匹配；不提供税号真实性、工商信息或税务合规认证。
- 输出建议表：字段 | 角色标签 | 原文 | 来源 | 判断 | 补充条件。缺标签时请求能显示对应栏位的材料。


## 章节：invoice-review-handoff

# 交接摘要结构

1. 身份：candidateId、sequence、origin、basedOnCandidateId（如有）、jobId 和 documentRef，使用工具实际值。
2. 关键字段：发票号码、开票日期、买卖方、币种及金额。raw/normalized/state 分开描述；unknown 不写成空字符串、零或已确认值。
3. 明细概况：按当前读取的行数及状态说明，不把商品文字直接当作所有明细已经完整核验。
4. 依据：关键结论附真实 SourceRef 和原文片段；check_invoice_sources 仅证明引用匹配，不能证明外部真实性或全部业务判断正确。
5. 未解决事项：保留实际 checks/issues 及未验证条件，区分人工提供、文档提取、缺失、歧义及无法辨认。
6. 下一步：列出人工需确认的选择或补充资料；已有工具可支持的操作写成建议，不写成已经执行。

摘要是当前读取范围的交接信息；它不触发导出，也不代表用户接受候选或任务完成。若部分内容无法取得，保留候选身份并明确缩小摘要范围，不隐去失败项。


## 章节：invoice-source-audit

# 来源与支持关系

- 业务来源引用使用实际工具返回的 documentId、version、artifactId、page、blockId、quote 等字段；旧版本、其他文档和不存在的块需要真实检查。
- quote 是被引用的原文，不是重写的总结；规范化值可与 raw 不同，但来源仍应支持原始事实。
- 卖方与买方、净额与总额、单价与合计的上下文关系分别核对，单纯命中同一个字符串不能证明字段归属。
- 来源有效并不证明候选所有约束合法；候选校验、保存和接受沿各自工具回执。
- 图片资料未在本工具可读范围时记为需要人工查看；不能从 Skill 正文或模型记忆补造发票证据。
- 发现错误引用后提出可核验的替代来源或资料缺口，修订仍需当前任务允许的操作。
