当前保留评测总方案；评测实现、测试、配置及 P0 阶段方案已删除，没有可执行的评测命令或当前通过结论。

后续按实际阶段创建 `docs/plans/` 阶段方案、`src/` 设施、`tests/` 自检和 `config/` 非秘密配置。真实 Case/Gold、Good/Bad 池及报告存于 Git 忽略的 `data/`；已有私有历史数据如存在则保留，不作为新阶段证据。

评测总方案已于 2026-09-14 对齐产品主方案第 21 章 P0–P13 Harness 功能建设轴：P0 验证基础契约与存储，P1 开始真实 Agent 接入，P12 验证完整桌面与模拟/真实测试业务链，P13 建立 Host 及 Test → Shadow → Canary → Production 生产质量放行轴。每阶段评测本次新增能力并回归受影响的前序能力；历史阶段标签和成绩不能直接作为新阶段验收依据。

阶段方案按 `P0_Agent评测实施方案.md` 至 `P13_Agent评测实施方案.md` 命名，进入对应阶段才创建；质量数据按 `data/P0` 至 `data/P13` 组织。后续按实际能力增量建设 Runner、Grader 和报告，Case/Gold 可提前准备，实际效果评测须等待能力可运行。产品代码不得依赖评测实现，主子 Session 的资源发现、文件访问、Context 和工具范围必须排除整个 `agent-eval/`。质量结论不授予生产写权限。

评测总方案第 3.23 节已同步产品业务 Workspace 与运行资源生命周期：P0 验证默认空间身份/归属，后续验证策略交集、暂停/归档、同空间会话绑定，以及 `runtime/<runId>/work/`、`agent/` 与 `sessions/` 持久历史分离。对应 MOD/RTC/BM、Case/Grader 证据和 P0–P13 阶段要求同步；清理后续接、父子资源隔离、原实例恢复与独立测试副本分别核验。首版单默认空间，不据此宣称多租户隔离，以上仍是设计要求而非已执行成绩。
