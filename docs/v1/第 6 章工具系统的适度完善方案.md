
# 第 6 章工具系统的适度完善方案

## 1. 审查结论与修改定位

**第 6 章的主体设计已经完整，不需要重做。** 已覆盖三类工具、定义与实现绑定、共享准入、Scope、四类 effect、返回契约、重试、取消和状态转换。

需要澄清的主要是：产品工具契约与 SDK 契约的区别、工具集合边界、动作申请与提交审批的先后，以及调用失败与业务事实之间的关系。

本次只完善主方案的职责和关键行为。具体 SDK 映射、接口字段、并发参数及测试步骤留到阶段方案。

## 2. 第 6 章的必要调整

### 2.1 区分产品契约与 Pi 工具定义

调整 §6.2–6.2.1：

- ToolSpec 是产品完整契约；模型只接收选择和调用工具所需的名称、描述及输入约束。
- `outputSchema` 用于产品校验业务结果，不因写在“模型可见契约”中，就意味着所有 Provider 或 Pi 原生工具都支持对应的输出约束。
- ToolResult 是产品结果封套，由 runtime-pi 转换为适用的原生工具结果；不将其描述为 Pi 的原生返回类型。
- Pi 原生及扩展工具保留自身实现和返回形式，由接入层接入必要控制与记录，不强制重写成业务 Handler。

保留既有七项工具概念，不新增抽象层。

### 2.2 明确工具集合与实际可调用范围

补充 §6.1.1、§6.2.1：

- 已注册、已装配并向模型提供、当前允许执行是不同事实。注册成功不代表每个 Run 都可以调用。
- Run 使用固定工具快照；工具仍在模型可见列表中，也不能绕过当前撤销或权限检查。
- 三类工具在同一 Session 中的对外名称不得产生歧义，冲突在装配时拒绝，不按加载顺序静默覆盖。
- 工具或实现版本的新增、替换通过既有受控装配和重绑规则生效，不悄悄改变活动执行。

具体清单结构和装配入口由对应阶段确定。

### 2.3 统一动作申请与审批边界

当前 §6.2.2 的“创建已授权动作意图”，与 §12.3.1 的“先创建冻结动作，再等待审批”容易产生误读。

统一为：

- Agent 可以在具备申请资格时，请求创建冻结动作及审批事项；**申请资格不等于发送许可**。
- 意图创建后可以处于 `awaiting_confirmation`，工具返回 `accepted/actionRef`。
- 实际发送必须由 submissions 读取有效审批并完成最终准入，保持唯一外部写入口。
- `EXTERNAL_WRITE` 按其所申请的外部业务效果接受治理，不表示 Handler 直接执行外部写。
- 将 §6.4“增加复核/审批”的表述明确为：Agent 可请求人工复核、申请审批及查询状态；人工确认和批准通过可信人工命令完成，不作为 Agent 自行批准的工具能力。

同步 §6.3 流程图中的“获准外部动作”，区分获准申请与获准发送，不改变既有动作状态。

### 2.4 区分重复调用、内部重试与业务防重

补充 §6.1.1、§6.3.2：

- 同一原生工具调用的重复交付复用原调用记录及已有结果，不再次执行 Handler。
- Gateway 内部 READ 重试属于一次工具调用，保留一条调用记录。
- 模型再次发起调用，即使参数相同，也属于新的工具调用；业务写是否重复，由既有命令及动作幂等规则判断，不能仅凭新的 toolCallId 获得重写权限。
- Pi 负责原生工具调度；Flowmate 负责逐调用准入及业务并发约束，不新增工具调度器。多工具结果按实际调用身份关联，不依赖完成顺序推断归属。

具体 SDK 调度模式、并发限制和幂等键实现留到阶段方案。

### 2.5 明确结果校验失败后的事实处理

补充 §6.2.2、§6.3、§6.5：

- 执行结果、持久业务事实和向 Pi 回送是否成功分别判断；回送失败不能证明业务未执行。
- 输出不符合契约时，不向模型伪装为合法成功结果。
- 若命令已经提交或外部效果可能发生，保留原身份和已知事实，按原命令或动作核对；不能因为结果格式错误、超时或回送丢失而重新执行。
- 工具结果中的错误、来源文本和下一步建议属于信息，不授予新权限，也不能绕过 Run 的目标、预算与终止条件。
- 沿用现有状态枚举和错误边界，不新增“输出失败”等状态。

## 4. 验收与细节边界

文档验收重点：

- 产品 ToolSpec／ToolResult 与 Pi 原生契约不混淆。
- 工具注册、模型可见和执行获准不混为一谈。
- 动作可以先申请再审批，Agent 不能自行批准。
- 重复交付、内部重试和模型新调用分别处理。
- 输出校验或回送失败不抹除已提交事实，也不授予重发权。
- 正文、流程图、状态表和评测要求一致。

保持三类工具路线、现有目录、23 张表、状态枚举及 P0–P13 顺序。不生成产品代码，不修改已发布评测资产。

精确 SDK 类型、结果映射、并发模式、超时数值、事务实现及具体测试步骤，由对应阶段方案确定。
