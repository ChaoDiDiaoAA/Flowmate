## 2. 数据事实及其含义

### 文件角色

以 `D:\paper\Invoice\voxel51\000001` 为例：

| 文件 | 实际角色 | 可用方式 |
|---|---|---|
| `original.jpg` | 原始票据图像 | 阅读、复核和原图输入测试 |
| `content.json` / `content.md` / `pages.json` | MinerU 文字、表格及版面解析 | 业务字段抽取的输入、定位原文证据 |
| `parse.json` | 解析尝试、版本、输入及输出 hash | 判断派生数据对应关系和完整性 |
| `annotation.json` | 数据集提供方的标注 | 参考标签来源 |
| `fields.json` | 从提供方标注映射的业务标签 | 下游流程测试输入，或独立评估参考；两种用途需隔离 |
| `record.json` / `snapshot.json` / `receipt.json` | 样本身份、来源、引用及采集信息 | 建立本地数据清单 |

`fields.json.provenance.kind=dataset_annotation`，并有 `mapping_version=voxel51/1`。它不是 Flowmate 从 MinerU 输出预测出的字段。

样本标签中，币种、净额、税率可以是 `missing`，税额可以是 `ambiguous`；票号、日期等可以是 `provided`。不得把这些状态全部降为“非空即正确”，也不得把缺失值填零或根据语言猜币种。

`dataset.json` 的 `record_count=8181` 描述来源数据集，不能当作本地可用数量。审查过程中本地派生文件数发生增长，因此所有数量都只能视为时点快照，不能作为冻结发布清单。

195 份标签中，buyer_name、buyer_address、seller_name、seller_address、invoice_number、invoice_date、total_amount 均为非空 `provided`；currency、net_amount、tax_rate、geometry 全部为 `missing`，tax_amount 全部为 `ambiguous`。缺失的是标签，不等于原图不存在对应信息。当前标签未覆盖中国增值税票验收需要的完整字段口径。

抽样查看了 000001、000006、000200 的原图。000200 的金额标签使用 `633,96`，000001 使用 `232.95`，需要明确小数与千位分隔的规范化规则。000200 票面明细金额之和为 633.97，而总额写为 633.96；应保留票面值及计算差异，按业务容差复核，不能静默改写原文。

已登记的 200 条记录都是英文 invoice，`layout_group=null`；抽样中存在相近版式。后续划分开发与回归集应按来源、版式或近重复样本分组，避免同模板泄漏造成过高估计。63 份完整配对样本足够启动验证，不代表覆盖真实业务分布。

本地记录声明来源为 Hugging Face / Voxel51，允许用途为 development、regression；所查记录的 `quality_status=not_checked`、`origin_kind=unknown`。原始文件存在不等于企业生产分布已具备，提供方标注存在不等于已经通过业务验收。本次不对数据真实性或许可证作超出现有证据的结论。

目录未提供可验证的目标企业供应商主数据、PO、真实审批记录、07B2B 录入结果或 ERP 回写结果。现有数据可以检验票据处理，无法单独检验这些外部业务环节。

样本 `parse.json` 中仍有 `D:\agent-data\data\flowmate-data` 的旧绝对目录，而当前数据位于 `D:\paper\Invoice`。接入时应解析逻辑根引用、校验实际文件及 hash；旧路径保留为历史信息，不能直接作为当前读取路径。

### 必须区分的两条测试路径

1. **下游流程回放**：读取 `fields.json` 作为已给定的字段输入，测试标准化、规则、复核、预览、提交模拟和恢复。这证明后半程流程能力，不证明 OCR 或抽取准确率。
2. **文档抽取评估**：模型或抽取程序只读取原图或 `content.*`，生成独立预测；评估器再读取标注比较。`fields.json`、`annotation.json` 以及携带答案的元数据不得进入模型上下文或可访问工具。

两条路径可以共用业务字段契约，但输入模式、产物目录和统计口径必须可辨认。标注歧义应保留并单独复核；确认为标注有误的项目才修订参考答案，并记录修订原因。

### Pi Runtime 边界补充

复用 Pi 的方向可保留，但“完整复用能力”不能等同于“启用默认所有工具与资源”。查阅日的官方 SDK 文档列出了默认文件/命令工具和资源发现规则；因此需要显式限制产品可用工具与资源来源，再将业务工具接到 Gateway。具体配置以锁定版本的验证为准。[Pi SDK 官方文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md)

建议做一个有边界的集成验证：固定版本，完成工具调用、事件映射、中止与重新创建会话，并证明默认工具和未批准扩展不能绕过业务 Gateway。Session 恢复与业务任务恢复分别验证。无需先建设完整 Skill 注册中心、Eval 后台或通用 Workflow Designer。
