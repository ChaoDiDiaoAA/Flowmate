# Flowmate 单人开发总导航

> 本文件是整个项目的唯一入口。你每次开始工作先打开它，只进入“当前阶段”对应的教程，不要同时推进多个产品阶段。

根目录中的 `07B2B_数字化员工平台_分阶段开发方案_V1.2.md` 保留为历史设计背景，不再作为逐步执行入口。遇到两者表述不一致时，以本目录的总导航、白话架构和当前阶段教程为准；重要架构变化先同步修改这三处，再开始编码。

## 1. 这个项目最终要做成什么

Flowmate 的第一个数字员工负责完成：

```text
接收真实发票
→ 提取并校验字段
→ 匹配供应商和采购订单
→ 请求必要的人工确认
→ 录入 07B2B
→ 确认提交结果
→ 回写业务系统
→ 保存完整审计证据
```

最终交付不是“演示一次成功”，而是同时满足：

- 正常任务可以稳定完成；
- 异常任务会停下来并告诉你原因；
- 未经批准不会执行高风险写操作；
- 超时后不会盲目重复提交；
- 每次操作都能追踪、回放和恢复；
- 你一个人能够备份、升级、回滚和排错。

## 2. 为一个人开发主动缩小范围

第一版只支持：

```text
1 个数字员工：07B2B 发票录入员
1 个业务流程：发票录入
1 个 07B2B 平台
1 套部署方式
1 个操作者
单机优先
SQLite 优先
单 Agent
```

第一版明确不做：

- 多租户；
- 多 Agent 编排；
- Kubernetes、Kafka、Redis；
- 微服务；
- 图形化 Workflow Designer；
- 插件市场；
- 自研 LLM Provider、Agent Loop、Streaming、Compaction；
- 无人监管的全量生产写入。

## 3. 两条流水线

产品开发和真实数据必须并行，但产品阶段只能按顺序前进。

```text
基础准备：00 → 01 → 02 → 03

产品流水线：A → B → C → D → E → F → G
              │    │    │    │    │
数据流水线：  DATA-01 → DATA-02 → DATA-03
```

对应关系：

| 产品阶段 | 必须具备的数据成果 |
|---|---|
| A 全 Mock MVP | 固定 Mock Scenario；可有 10～20 张脱敏发票用于理解业务 |
| B 真实 OCR | DATA-02 产出的真实发票和人工正确字段 |
| C 真实测试环境 | 测试账号、测试供应商、测试 PO、测试规则和测试发票 |
| D Shadow | DATA-03 发布的生产分布验收集、真实只读业务数据 |
| E Canary | 已授权机器人账号、低风险白名单、回滚方案 |
| F 正式交付 | 所有生产 Provider、回写、监控、备份和验收数据 |
| G 单人运维 | 可恢复备份、故障手册、升级回归集 |

## 5. 每次工作固定采用这个循环

```text
打开当前教程
→ 只选择一个未完成复选框
→ 把该步骤和相关文件交给 AI
→ 查看 AI 修改了什么
→ 运行教程指定的检查命令
→ 人工看一次实际画面
→ 测试通过
→ Git 保存点
→ 勾选步骤
```

建议每次只让 AI 完成一个可验证任务，不使用“把整个阶段全部做完”这样的提示词。

## 6. 给 AI 编码助手的固定开场提示

每次新对话先复制下面这段：

```text
你正在帮助一名只会 Vibe Coding 的独立开发者开发 Flowmate。

请先阅读：
1. docs/07b2b/00_从这里开始_项目总导航.md
2. 当前阶段教程
3. 当前步骤明确列出的相关文件

规则：
- 一次只完成当前复选框；
- 修改前先说明会改哪些文件；
- 不扩大范围；
- 不引入微服务、Redis、Kafka、Kubernetes、多 Agent；
- 不自研 Pi 已提供的 Runtime 能力；
- 先写或更新测试，再实现；
- 完成后运行教程中的验证命令；
- 明确列出修改内容、测试结果和仍存在的风险；
- 测试失败时停止，不进入下一步；
- 不读取、输出或提交真实密码、API Key、发票敏感信息。
```

## 7. 三种责任标记

所有教程使用以下标记：

- `🤖`：AI 可以在项目目录内完成；
- `👤`：必须由你亲自检查或操作；
- `🏢`：必须由财务、采购、ERP、07B2B、IT 或信息安全人员提供或批准。

“一个人开发”是指只有一名工程开发维护人员，不代表可以绕过真实数据所有者、业务审批和生产授权。

## 8. 全局禁止继续条件

出现以下任一情况，停止当前阶段：

- 测试没有全部通过；
- 不知道修改影响了哪些文件；
- 真实数据没有完成脱敏和授权；
- 密钥出现在源码、Markdown、截图或 Git 中；
- 没有备份就准备修改生产数据；
- 没有 Kill Switch 和回滚演练就准备 Canary；
- B2B 提交超时后无法查询最终状态；
- 最终验收集被用于修改 Prompt、规则或代码；
- 需要绕过验证码、MFA、扫码或平台安全机制。
