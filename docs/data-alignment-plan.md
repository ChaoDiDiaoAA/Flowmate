# Flowmate 数据集对齐修订方案

## 交付约束

按用户确认，仅交付一套当前质量数据。固定 `manifests/audit/`、`manifests/materialization/` 和 `manifests/inventory.json`；目录和资产文件名不追加版本后缀。原票共 2,902 份，核验候选 1,200 份，模拟资料 600 套，七类用例合计 6,000 个。

机器准备期间的有效修订合入当前资产，必要来源摘要保留在元数据。实际人工审核和运行历史产生后必须保留其内容和身份。原图不复制为多套，不因修订清理；审核和运行状态不由脚本代填为成功。

## 逐项修订

| 审查项 | 修订内容 | 接收依据 |
|---|---|---|
| A01 完成判据不足 | `oracle.checks` 明确必要项、硬约束、维度、证据和规则实现状态；局部断言不能充当整例通过 | 未实现规则或缺证据阻断通过；真实证据入口验证受信来源与内容摘要 |
| A02 缺证据掩盖失败 | 聚合先保留已确认必要项失败，再列出未解决项 | 同时存在 FAIL 与缺证据时保留 FAIL 和缺口 |
| A03 安全维度混用 | 分别评模型行为、平台控制及实际后果，并检查攻击是否真实到达 | 网关拒绝不能掩盖模型越权请求；真实后果独立记录 |
| A04 合法对照循环 | 基础合法对照独立；攻击绑定同用途、同操作的对照身份和修订 | 不接受输入中伪造的对照 pass；对照必须独立加载并重新评分 |
| A05 夹具并非单故障 | 构造有效非空解析、图片引用、原图和元数据底包，再引入缺图、摘要不符等变化 | 基础合法包可核对，故障范围明确，未真实执行导入不声称导入通过 |
| A06 路径越界不触及目标 | 受控临时根下建立合成哨兵，越界路径实际指向目标 | 临时目录读取得到预设哨兵；受保护目标不进允许根 |
| A07 主方案映射不足 | 固定主方案摘要、MOD/RT/RTC/RTX、Driving Task 和关键横切条文；检查级引用并报告缺口 | 条目存在不等于条款全部覆盖；F/A/B 未准备变体保留缺口 |
| A08 阶段过晚 | 原生历史损坏场景归 P4；衍生视图同步刷新 | 保留相关用例身份，阶段和视图一致 |
| A09 审核入口不足 | 支持 Gold、business、case、policy；目标摘要、Owner、检查项、证据、暴露、争议和裁决 | 空表不能通过，实际记录留存父内容，审核通过不自动成为验收资格 |

## 数据调整原则

1. 固定四项总预算和七类用例数量，不通过增加同 ID 副本凑数。
2. 原票抽取仍一票一例，原票金额与模拟金额分别使用。
3. 对运行、安全、平台的重复分配补充具体初态、触发和原子预期；纯机制用例清除无关原票输入。
4. 全局语义键计数与重复序号一致；同票关联仍不是独立企业样本。
5. 原票及近重复组继承同一用途；当前不声称未见模板或未见供应商泛化。
6. 新目录索引、用途成员、阶段/BM 视图、审核批次和物化摘要从当前资产重新生成。
7. 未人工核验的 Gold 保持不可正式评分；所有当前产品用例保持未运行。

## 实施与检查顺序

1. 核对旧质量清单、有效修订及产品来源摘要，确认没有真实审核/运行历史被误作草案。
2. 修复评分与夹具并运行针对问题的设施自检。
3. 从当前两份主方案提取需求，重编具体场景和检查项，验证 ID、数量和用途不漂移。
4. 在项目暂存目录生成唯一当前数据；原票分析摘要符合时复用近重复线索，重新生成依赖场景目录的任务单。
5. 全量检查原票、解析、图片引用、质量摘要、算术、配额、需求映射、合法对照及生命周期。
6. 检查成功后受控替换质量根并移除已退役机器草案目录；替换后再次检查。
7. 人工核验、产品接入和真实 SDK/企业接口运行另按实际阶段完成，不能伪造成当前成果。

## 当前命令和文件

- `agent-eval/tools/finalize_invoice_data.py`：检查并暂存单一当前数据，拒绝清理真实审核/运行历史。
- `agent-eval/tools/invoice_requirements.py`：需求提取、用例丰富、覆盖报告及映射检查。
- `agent-eval/tools/invoice_case_catalog.py`：业务与机制场景定义。
- `agent-eval/tools/review_invoice_data.py`：实际审核入口、当前资产及统一清单。
- `agent-eval/tools/verify_invoice_data.py`：产品及质量数据完整性和生命周期检查。
- `agent-eval/src/runner/`、`graders/`、`contracts.py`：离线物化、模拟目标、受信证据和逐项评分。
- `agent-eval/tools/test_invoice*.py`、`agent-eval/tests/`：制作、审核、场景与评分设施自检。

日常检查运行 `python agent-eval/tools/verify_invoice_data.py --project .`，不需要选择历史发布号。目录职责、详细制作规则和审核命令统一维护于 [数据制作方案](data-preparation.md)；当前数量和缺口由 `agent-eval/data/manifests/preparation-report.json`、`coverage.json` 与 `materialization/report.json` 给出。

## 完成边界

工程修订完成表示当前材料和设施通过对应检查，不表示 1,200 份人工核验已完成，也不表示 6,000 个产品用例已执行。覆盖报告中的 `partial_prepared` 和 `uncovered` 是制作状态；现阶段没有完整需求通过率或真实业务自动化率。
